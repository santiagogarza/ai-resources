# Product Psychology & UX Design Skill

This skill encodes the core frameworks, cognitive biases, checklists, and case study patterns from Growth.Design's Product Psychology Masterclass. Use it to build better products grounded in how humans actually think and behave.

## When to Use This Skill

Apply this skill whenever you are:
- Designing or reviewing any user interface or experience
- Building onboarding, retention, conversion, or referral flows
- Writing microcopy, error messages, or notifications
- Evaluating whether a design is ethical or manipulative
- Planning a product feature and need to anticipate user behavior
- Doing a UX audit or product assessment
- Creating landing pages, signup flows, or checkout experiences

## Core Mental Model: The 4-Step Decision Cycle

Every time users interact with a product, they go through four mental steps. All cognitive biases and UX principles map to one of these:

1. **Information** — Users filter out most of what they see, even when it's important
2. **Meaning** — Users fill gaps with stories and assumptions to make sense of things
3. **Time** — Users are busy, so they look for shortcuts and jump to conclusions
4. **Memory** — Users try to remember what's important, but their brain is selective

When designing any interface, ask: "At this step, is the user filtering, interpreting, acting, or remembering — and which biases are at play?"

## Quick-Reference: The B.I.A.S. Framework

For any screen or flow, run through these four lenses:

- **B — Block**: Does this pass the user's brain filters? Is it noticeable, not ad-like, low-effort looking, and well-timed?
- **I — Interpret**: Can users quickly understand this? Is cognitive load low, are patterns familiar, are benefits clear?
- **A — Act**: Can users easily take action? Are there too many decisions? Are defaults smart? Are steps broken down?
- **S — Store**: Will users remember this positively? Is there clear feedback, reassurance, delight, and a sense of care?

## Quick-Reference: Behavior Mapping (Motivation + Ability + Prompt)

Before a user takes any action, three things must converge:
- **Motivation**: Does the user want to do this? (Hopes, pains, social pressure)
- **Ability**: Can the user do this? (Time, money, mental effort, physical effort, practice)
- **Prompt**: Is the user being nudged to do this at the right moment?

If any one of these is missing, the behavior won't happen. When a feature isn't working, diagnose which of the three is failing.

## Quick-Reference: Journey Design (Peak-End Rule)

Users judge experiences by their **peak moment** (best or worst) and **how it ends**, not by the average. When designing journeys:
- Identify and elevate the peak positive moment
- Fix or remove the deepest negative pit
- Always end on a high note
- Mark transitions/milestones proportionally to their importance
- Turn waiting periods into value (Labor Illusion)

## Quick-Reference: Ethical Design Tests

Before shipping any feature, run these tests:

### Regret Test
- If a user was in the room while you discuss this feature, would you say the same things?
- If users knew what your team knows, would they take the same action?

### Black Mirror Test
- What would using your product "too much" look like?
- Who or what disappears if your feature becomes wildly successful?
- List all potential negative side effects, then brainstorm prevention.

### Humane Principles
- Does your product help users save time?
- Does it value users' attention (no false notifications)?
- Does it reflect human values?
- The "In Real Life" test: If your interface were a person, would you want to hang out with them?

## Quick-Reference: The Hooked Model (Habit Formation)

Products become habits through a 4-phase loop:
1. **Trigger** → Internal (emotion: boredom, loneliness, FOMO) or External (notification, email, ad icon)
2. **Action** → The simplest possible behavior in anticipation of reward (swipe, scroll, tap). Always maximize Ability before Motivation.
3. **Variable Reward** → Unpredictable payoff in three flavors: Tribe (social), Hunt (information/resources), Self (mastery/completion). Variability is what sustains engagement.
4. **Investment** → User puts something back in (data, content, connections, reputation) which improves the next loop and loads the next trigger.

The best products layer all three reward types and ensure investment creates compounding stored value.

## Quick-Reference: Dieter Rams' Design Bar

When reviewing any interface, check these 10 principles:
1. **Innovative** — Advances what's possible for the user (not just novel chrome)
2. **Useful** — Every element serves a real user need
3. **Aesthetic** — Crafted and harmonious (beautiful UIs are perceived as easier to use)
4. **Understandable** — Self-evident without tutorials
5. **Unobtrusive** — The UI disappears; user's content/task is the star
6. **Honest** — No dark patterns, no fake data, no manipulation
7. **Long-lasting** — Built on timeless principles, not trends
8. **Thorough** — Edge cases, micro-interactions, and accessibility handled
9. **Environmentally friendly** — Respects attention, time, battery, and data
10. **As little as possible** — Everything non-essential removed. "Less, but better."

## Quick-Reference: Zero-Friction Design

Friction exists at three layers — each deeper and harder to detect:
- **Interaction Friction** (surface): Too many taps, small targets, slow loads, unnecessary fields
- **Cognitive Friction** (mental): Unclear labels, too many choices, jargon, unpredictable outcomes
- **Emotional Friction** (deepest): Fear of commitment, trust anxiety, social embarrassment, overwhelm

**The rule**: Remove friction from the path to value. Add friction only before the path to regret.

## Quick-Reference: Product Classification

- **Painkillers**: Solve urgent pain (Uber, Zoom). Fast adoption, organic retention.
- **Vitamins**: Long-term value, no urgency (meditation apps, journaling). Fragile retention.
- **Gummy Vitamins**: The holy grail — "good for you" wrapped in "can't stop" (Duolingo, Tinder, Strava, Claude). Users come for the fun, stay for the value.

To turn a Vitamin into a Gummy Vitamin: add variable rewards, reduce action to near-zero effort, add streaks/commitment, create social connection, make progress visible, and lower the stakes of each session.

## How to Apply This Skill

### For UI/UX Reviews
1. Read `references/cognitive-biases.md` for the relevant category
2. Walk through the B.I.A.S. framework for each screen
3. Check against `references/product-assessment-checklist.md`

### For New Feature Design
1. Start with Behavior Mapping (Motivation + Ability + Prompt)
2. Sketch a 6P Story (Person, Problem, Promise, Process, Proof, Payoff)
3. Apply the B.I.A.S. framework to each screen
4. Map the journey and apply Peak-End Rule
5. Run the ethical tests before shipping

### For Product Assessments
1. Read and follow `references/product-assessment-checklist.md` end-to-end
2. Cross-reference findings with `references/cognitive-biases.md`
3. Use `references/case-studies.md` for benchmarking against best practices
